# GraceFM

近距離モニター・放送向けの低遅延音声伝送方式とPython参照実装。短いHaarフレーム、FEC付きヘッダとHaar係数部の分離、階層変調、任意の2系統融合で、受信条件に応じた音質低下を扱う。実RF・実時間動作は未実証。

## 現行プロファイル

**区間アッテネータは全主系・副系の標準機能。** 名前の数値は系列名で、実ビットレートは設定マトリクスを参照。

| 用途 | 構成 | QPSK | 階層16QAM | 階層16QAM＋QASK |
|---|---|---|---|---|
| 32kHz主系 | モノラル | — | 1: B200M | 3: B200MY |
| 32kHz主系 | ステレオ | — | 2: B200 | 4: B200Y |
| 32kHz副系 | モノラル | 5: SUB50M | — | — |
| 32kHz副系 | ステレオ | 6: SUB100 | — | — |
| 48kHz主系 | モノラル | — | 7: M700M | 9: M700MY |
| 48kHz主系 | ステレオ | — | 8: M700 | 10: M700Y |
| 48kHz副系 | ステレオ | 11: SUB100-48K | — | — |

末尾の`M`はモノラル、`Y`は2 kHz以上の3帯域（48 kHzでは3 kHz以上）を位相・半径シンボルで送るQASKを表す（MY系はMのみ、Y系はMとS）。末尾に`M`がなければステレオ。`SUB` は別周波数で送る副系の名前で、ステレオ差分成分 `S=(L-R)/2` とは異なる。副系は雑音耐性を優先してQPSK、ステレオ主系のSは階層16QAMを使う。`SUB100-48K` は48 kHz主系用の約100 kbpsステレオ副系。

`—` は未定義の組合せで、自動生成しない。全登録プロファイルに区間アッテネータを標準装備する。

### 全設定と基本層・拡張層

**[プロファイル設定マトリクス](docs/PROFILES.md)** に、ID、サンプリング周波数、変調、FEC、M/Sの仮数全幅・基本層・拡張層、係数別昇格、区間アッテネータ、指数幅・オフセット、RRC、伝送予算を同じ項目で掲載する。設定元 `gracefm/profiles.py` から自動生成し、表と実装の不一致をチェックできる。

- フレームは**ヘッダ**と**Haar係数部**に分ける。FECは「位相部にパリティ、振幅部にデータ」を置く系統符号で、1シンボルが「パリティ2bit｜データ2bit」になる。ヘッダ（ヘッダ・指数・区間アッテネータ・CRC）はこの形で符号化し、係数は各係数の先頭シンボルが「パリティ＋最上位bit｜次の2bit」、以降のシンボルにはパリティがない。残りの仮数はFEC・CRCなし。
- フレームのHaar分解は4段（最低域の帯域幅が2 kHz未満になる段数。32 kHzも48 kHzも4段）。帯域は5つで、32 kHzでは0〜1、1〜2、2〜4、4〜8（H2）、8〜16 kHz（H1）。
- パリティが守る上位bit数Kは全帯域で1。QPSKには音声の基本層／拡張層の区分がない。
- Y帯域は7bit（最上位bit＋パリティが位相、残り6bitが半径）の専用シンボルで、仮数がHaar係数部に無い。通常デジタル層の区分は適用しない。
- **冗長経路の設計コンセプト**：別の局のB200系チャンネルの空き帯域に副系SUB50Mを置き、チャンネルを増やさずに冗長化する。副系は別送信機なので主系と電力を分け合わない。詳細と条件は[SPEC 5.2節](docs/SPEC.md)。
- 副系は別周波数で送る独立した音声ストリームで、M/SのS成分や拡張層とは別物。副系のアッテネータは各成分の最高送信帯域に置く。詳細な区間長は設定マトリクス参照。

## 仕様と検証状況

[技術論文](docs/SPEC.md)にHaar量子化、変調、FEC、欠損処理、フィルタ、フレーム形式、ビットレートと占有帯域をまとめた。ID 0・12～15は予約。

64サンプル／フレーム。処理時間・フィルタ遅延0の伝送時刻モデルは32kHzで4ms、48kHzで約2.667ms。送受信RRC・等化器・実処理・ADC/DAC・同期取得の遅延は別途必要。実装はオフラインの配列処理であり、実機の遅延保証ではない。

高域（H1/H2）とその他は別々のCRC（基本12 bit、高域10 bit）で検査する。基本CRC不一致はフレーム欠落、高域CRCだけの不一致はH1/H2を消去して低中域を採用する。出力段のポストフィルタは、Haar合成後のint32をLanczosで8倍にオーバーサンプリングし、LPFを通して48 kHz/int32へ落とす。主系の占有帯域は[測定結果](docs/SPEC.md)を参照。実RF・実時間動作は未実証。

[FM・aptX・HE-AAC・M700系比較](docs/COMPARISON.md)は方式ごとに条件と未測定項目を明示する。Y系の係数配置と伝送予算は[現行仕様](docs/SPEC.md)と[設定マトリクス](docs/PROFILES.md)を参照。

[試聴音源](samples/README.md)は標準アッテネータを含む現行設定で再生成する。ファイル名は[命名規則](samples/NAMING.md)に統一し、現行音源だけを掲載する。[全音源の設定・測定値・ハッシュ](samples/index.json)を参照。

## 使い方

```sh
pip install -r requirements.txt
python tools/sim/codec_wav.py 入力.wav 出力.wav --profile B200
python tools/sim/sim_link.py 入力.wav 出力.wav --profile B200M --snr 8 --single
python tools/samples/regenerate_samples.py     # 現行音源・評価値・試聴ページを一括再生成（評価依存が必要）
python tools/report/profile_matrix.py          # 設定表と計算予算を更新
python tools/report/profile_matrix.py --check  # 実装との一致を確認
python tests/test_profiles.py
python tests/test_gracefm.py
python tests/test_y.py
python tests/test_equalizer.py
```

評価を実行するツールは現行プロファイル名で動作する。各ツールの `--help` を参照。

## 構成

- `gracefm/`：プロファイル・音声符号化・変復調・FEC・融合・PLC・時刻モデル。
- `tools/`：`sim/`（WAV変換・シミュレーション）、`report/`（設定表・スペクトル・基本層の生成）、`samples/`（試聴音源の生成と検証）、`eval/`（評価）。
- `tests/`：プロファイル、アッテネータ保護、実配置、送受信、等化の検証。
- `docs/`：現行仕様、設定表、評価結果。
- `samples/`：現行仕様で生成した試聴音源と出典。
