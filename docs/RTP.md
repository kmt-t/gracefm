# GraceFM/RTP

GraceFM/RTP は、電波で送られた GraceFM のフレームを、受信機のフロントエンドからデコーダへ IP 網越しに渡すための RTP ペイロード形式である。ハイレゾのリアルタイム音声配信に使う。以下は設計であり、実装も評価もない。評価していない項目は「未評価」と書く。

## 1. 位置づけ

```
電波 → 受信機フロントエンド（同期・等化・シンボル判定）→ RTP/UDP/IP → デコーダ（フレーム層以降）
```

- 送るデータはデジタルである。フロントエンドが判定したフレームのビット列（ヘッダとデータ）を、そのまま送る。
- **ズレ**（信頼ビット）は、オプションで添える。ズレがあれば、デコーダは受信シンボルを復元して通常の LLR を作る。ズレがなければ、硬判定のビットとスケール（§3.2）から LLR を作る。
- **ズレは GraceFM/RTP だけが使う**。電波のフレーム形式には含まれず、[SPEC](SPEC.md) のビットレートや占有帯域に影響しない。
- プリアンブル（16 シンボル）は送らない。同期と等化はフロントエンド側で済んでいるためである。

## 2. 送るもの

フレーム 1 つ（= 1 ブロック = 64 サンプル）について、次を順に送る。

1. **スケール** 1 byte（§3.2）
2. **フレームのビット列** — ヘッダ、CRC、系統符号のパリティ、仮数、詰め物を含む `n_tx` bit。デスクランブル済みで、[SPEC](SPEC.md) 3節のビット配置のまま（デコーダの `unpack` の入力と同じ）。上位 bit から詰め、byte 単位に切り上げ、余りは 0 にする。
3. **Y 専用シンボルのデータ**（Y 系だけ）— Y 係数ごとに 9 bit、Y 専用シンボルの順に隙間なく詰める（上位 bit から、最後は byte 単位に切り上げ、余りは 0）。上位から、仮数の最上位 bit 1、そのパリティ 1、半径 7 bit（デスクランブル済み）。半径は、受信点の大きさ $`|z|`$ から求めた半径の段（0〜63）の連続値 $`\hat L = (|z|\,s_Y - 1)/a + 31.5`$（$`s_Y`$ は `modem.y_scale`、$`a`$ は Y の振幅 `y_amplitude`）を、スクランブルのマスクで反転していた分（$`63 - \hat L`$）を戻したうえで、$`\mathrm{round}(2\hat L)`$ にして 0〜127 に切り詰めた値である（段の間を 1/2 刻み）。
4. **ズレ**（`deviation=2` のときだけ）— §2.1。

### 2.1 ズレ（オプション）

等化とゲイン・位相の補正を終えた受信シンボルを $`z`$ とする。電波上の信号点のうち最も近い点（フロントエンドの硬判定を、スクランブルをかけて変調した点）を $`\hat s`$ とし、ズレは $`e = z - \hat s`$（I 軸・Q 軸の実数 2 つ）である。
ズレは軸ごとに 2 bit に量子化する。量子化幅 $`\Delta`$ はフレームごとに 1 つで、

| 符号 $`q`$ | 範囲 | 復元値 |
|---|---|---|
| 0 | $`e < -\Delta`$ | $`-1.5\Delta`$ |
| 1 | $`-\Delta \le e < 0`$ | $`-0.5\Delta`$ |
| 2 | $`0 \le e < \Delta`$ | $`+0.5\Delta`$ |
| 3 | $`e \ge \Delta`$ | $`+1.5\Delta`$ |

送り側は、そのフレームのズレの二乗平均（軸あたり）から $`\Delta`$ を決める。既定は $`\Delta = \hat\sigma`$（軸あたりの雑音の標準偏差の推定値）である。

1 シンボルのズレは 4 bit（$`q_I`$ の 2 bit、続いて $`q_Q`$ の 2 bit）で、デジタルシンボルの順に並べる。上位 bit から詰め、byte 単位に切り上げ、余りは 0 にする。Y 専用シンボルにはズレを付けない（半径は 7 bit で送り、位相は最上位 bit とパリティで送る）。

デコーダは、デジタルシンボルについて、ビット列を電波と同じにスクランブルして変調した点に、ズレの復元値を足して $`z' = \hat s + e'`$ を作る。雑音分散は $`\hat\sigma^2 = \Delta^2`$ として、通常の LLR の計算に渡す。

## 3. RTP パケット

### 3.1 RTP 固定ヘッダ

| 項目 | 値 |
|---|---|
| ペイロードタイプ | 動的（96〜127）。SDP の `rtpmap` で割り当てる |
| タイムスタンプ | クロックはプロファイルの $`f_s`$（32000 または 48000）。1 フレームで 64 増える。初期値は RFC 3550 に従い乱数 |
| シーケンス番号 | パケットごとに 1 増える |
| マーカー | ストリームの開始と、送り側の再同期の直後の最初のパケットに立てる |
| SSRC | 主系と副系は別の SSRC |

デコーダは、フレームの 16 bit のフレーム番号（フレームのヘッダ内）を、既存の仕組みで 32 bit に展開して使う。タイムスタンプは再生時刻の決定に使う。

### 3.2 ペイロード

| 位置 | サイズ | 内容 |
|---|---|---|
| 0 | 2 bit | バージョン $`V = 0` |
| 0 | 1 bit | $`D`$: 1 = ズレあり、0 = ズレなし |
| 0 | 5 bit | このパケットのフレーム数 $`F`$（1〜8） |
| 1 | 1 byte | 予約（0） |
| 2〜 | フレーム × $`F`$ | フレーム本体（§2） |

スケール $`S`$（0〜255）は、$`\Delta = 2^{(S-255)/16}`$ である。シンボルの平均エネルギーは 1 に正規化されているので、$`S = 255`$ は $`\Delta = 1`$ を表す。$`\Delta`$ は、ズレありでは量子化幅、ズレなしでは送り側の軸あたりの雑音の標準偏差の推定値である。ズレなしのデコーダは、これを雑音の推定値として、硬判定ビットの LLR の大きさと融合の重みに使う。この LLR の作り方は、未評価である。

フレーム 1 つの長さは、プロファイルとズレの有無で決まる（§4）。デコーダは SDP の `profile` から長さを知るので、フレームごとの長さの情報は持たない。

### 3.3 パケット化

1 パケットに入れるフレーム数 $`F`$ は、セッションで決める。パケットの時間長は $`F \times 64 / f_s`$ で、これだけ遅延が増える。ペイロードは 1400 byte 以下とし、$`F \in \{1, 2, 4, 8\}`$ のうち条件を満たす最大値を既定にする。

## 5. SDP

```
m=audio 5004 RTP/AVP 96
a=rtpmap:96 vnd.gracefm/32000
a=fmtp:96 profile=B200M; system=0; frames=4; deviation=2
a=ptime:8
```

| パラメータ | 意味 |
|---|---|
| `profile` | プロファイル名。フレーム本体の長さと変調が決まる |
| `system` | 0 = 主系、1 = 副系 |
| `frames` | 1 パケットのフレーム数 $`F`$ の既定値。ペイロードヘッダの $`F`$ が優先する |
| `deviation` | ズレの量子化 bit 数（軸ごと）。2 = ズレあり、0 = ズレなし。この版はこの 2 つだけ |

`vnd.gracefm` は暫定名で、メディアタイプは未登録である。

## 6. 主系と副系

主系と副系は別の RTP ストリーム（別の SSRC、SDP の別の `m=` 行）で運ぶ。デコーダが、フレーム番号で時刻をそろえて融合する（[SPEC](SPEC.md) 5節）。SDP の `a=group` で冗長ストリームとしてまとめる書き方は、未決である。

## 7. 損失、ジッタ、遅延

- パケットが失われると、そのパケットの $`F`$ フレームがまとめて失われる。デコーダは、フレームの欠損として既存の補間（LPC 外挿とクロスフェード）で処理する。$`F`$ フレームの連続欠損が音質にどう影響するかは、未評価である。
- この版には RTP レベルの FEC と再送はない。RTCP の SR/RR で損失率とジッタを報告する。
- デコーダの再生遅延は、最小の一定遅延（[SPEC](SPEC.md) 7節）に、ジッタバッファと、パケット化の遅延（§4 の表の「パケット長」）が加わる。

## 8. セキュリティ

電波で暗号化されたフレームは、暗号化されたままビット列として運ぶ。フロントエンドは鍵を持たず、復号はデコーダが行う（フレームのヘッダの暗号化フラグは平文である）。Y 帯域の暗号化は、電波の形式が未対応なので、GraceFM/RTP も未対応である。IP 区間の暗号化と認証には SRTP を併用できる。この版では SRTP との組み合わせを定義しない。

## 9. 未評価と未決の項目

- ズレなし（硬判定ビットとスケールだけ）の受信品質。ズレありとの差、特に低 C/N0 での差。
- ズレ 2 bit の量子化と $`\Delta = \hat\sigma`$ の選び方が、ViSQOL と波形 SNR に与える影響（量子化なしとの比較）。
- Y 専用シンボルの半径 7 bit（段の間 1/2 刻み）が十分か。また、半径を $`|z|`$ から求めることが、象限への射影を使う現行のデコーダに比べてどれだけ劣るか。
- 欠損が連続したときの音質（$`F`$ を変えた比較）。
- 主系と副系の冗長ストリームの SDP での表現。
- メディアタイプの登録、ペイロードヘッダの予約 byte の使い方、SRTP との組み合わせ。
